# Mockuper Metrics Bot

Telegram-бот, который каждый день в 9:00 присылает отчёт с метриками
приложения из PostHog. По понедельникам дополнительно приходит отчёт за
неделю, 1-го числа — за месяц.

Пример ежедневного отчёта:

```
📱 Mockup Clothing — Daily Report
📅 05 Jul 2026
━━━━━━━━━━━━━━━━━━━━

👥 Пользователи
  • DAU: 1
  • Запусков приложения: 5
  • Открыли редактор: 4

💰 Монетизация
  • Покупок: 0
  • Пейволл показан: 6
  • Конверсия: 0.0%

🎨 Контент
  • Мокапов сохранено: 1
  • AI-генераций: 0

👗 Топ гарментов
  • Classic T-Shirt: 4

🔓 Источники пейволла
  • default: 5
```

Бот **не трогает вебхуки** Telegram и не мешает существующей отправке
генераций из приложения через этот же токен — он только шлёт сообщения
и читает команды через long polling.

## Деньги и подписки (RevenueCat)

Если задать `REVENUECAT_API_KEY` и `REVENUECAT_PROJECT_ID`, в каждый отчёт
(день/неделя/месяц) добавляется денежная секция:

```
💵 Деньги за период
  • Выручка (gross): $547
  • В карман (после Apple): $459

📊 Сейчас
  • MRR: $1,758
  • Активных подписок: 185
  • ARPPU: $9.50/мес
  • Новых юзеров (28д): 1590
```

Выручка и снапшот берутся из RevenueCat API — работают сразу, ничего
настраивать не надо (ключ `sk_...` из Dashboard → Project settings → API keys,
достаточно read-only).

**Новые/продления/отписки за период** метрик-API не отдаёт, поэтому они
собираются из **вебхуков** RevenueCat:

1. Задеплойте бота как **web-сервис** (публичный URL; см. раздел про Render).
2. RevenueCat Dashboard → Integrations → Webhooks → URL
   `https://<ваш-сервис>/rc/webhook`, в поле Authorization впишите секрет и
   продублируйте его в переменную `RC_WEBHOOK_AUTH`.
3. После этого в отчёте появится секция:

```
🧾 Подписки за период
  • Новых: 12 (нед 9 / год 3)
  • Продлений: 34
  • Отписались (autorenew off): 7
  • Закончились: 5
```

> События вебхуков хранятся в файле на диске сервиса. На Render диск
> эфемерный — при редеплое накопленные события теряются (выручка и снапшот
> из API это не затрагивает).

## Команды бота

| Команда | Что делает |
|---|---|
| `/report` | Отчёт за вчера |
| `/today` | Отчёт за сегодня (неполный день) |
| `/week` | Отчёт за прошлую неделю (пн–вс) |
| `/month` | Отчёт за прошлый месяц |
| `/events` | Реальные имена событий в PostHog за 14 дней |
| `/props <event>` | Свойства события (чтобы настроить топ гарментов и т.п.) |
| `/chatid` | ID текущего чата (нужен для `TELEGRAM_CHAT_ID`) |

## Деплой на Render

Быстрый путь — скрипт, который делает всё сам (проверяет имена событий в
PostHog, создаёт background worker через Render API, шлёт тестовый отчёт
и прописывает `TELEGRAM_CHAT_ID`):

```bash
pip install -r requirements.txt
export RENDER_API_KEY=rnd_...
export POSTHOG_API_KEY=phx_...
export POSTHOG_PROJECT_ID=498457
export TELEGRAM_BOT_TOKEN=123:ABC...
# заранее напишите боту любое сообщение, чтобы скрипт нашёл chat_id
python scripts/bootstrap_render.py
```

Ручной путь через дашборд:

1. Запушьте репозиторий на GitHub (уже сделано).
2. На [render.com](https://render.com): **New → Blueprint**, выберите этот
   репозиторий — Render прочитает `render.yaml` и создаст background worker.
3. В настройках сервиса заполните секреты:
   - `TELEGRAM_BOT_TOKEN` — токен бота из @BotFather;
   - `POSTHOG_API_KEY` — personal API key (`phx_...`) из PostHog
     (Settings → Personal API Keys, нужен scope Query Read);
   - `TELEGRAM_CHAT_ID` — можно оставить пустым, задеплоить, написать боту
     `/chatid`, вписать полученный ID и сохранить.
4. После деплоя напишите боту `/report` — придёт отчёт за вчера.

> ⚠️ Background worker требует платного плана Render (Starter).
> Бесплатные варианты:
> - **Web Service (free)** + внешний пингер (например, cron-job.org каждые
>   10 минут): поменяйте тип сервиса на `web` — приложение само поднимет
>   health-endpoint на `PORT`. Без пингера Render усыпит сервис и отчёт
>   в 9:00 не отправится.
> - **Render Cron Job**: команда `python main.py --once daily` каждый день,
>   `--once weekly` по понедельникам, `--once monthly` 1-го числа
>   (в этом режиме команды бота в Telegram работать не будут).

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен бота |
| `TELEGRAM_CHAT_ID` | — | чат для отчётов (узнать: `/chatid`) |
| `POSTHOG_API_KEY` | — | personal API key `phx_...` |
| `POSTHOG_PROJECT_ID` | — | ID проекта (498457) |
| `POSTHOG_HOST` | `https://us.posthog.com` | регион PostHog |
| `REPORT_TZ` | `Europe/Moscow` | часовой пояс отчётов |
| `REPORT_HOUR` | `9` | час отправки ежедневного отчёта |
| `APP_NAME` | `Mockup Clothing` | название в шапке отчёта |
| `ENABLE_POLLING` | `1` | `0` — отключить команды в Telegram |

### Имена событий

Отчёт считает метрики по именам событий PostHog. Для каждой метрики задан
список кандидатов (см. `.env.example`) — суммируются все, что реально есть
в данных. Если какая-то цифра в отчёте нулевая, а в PostHog данные есть:

1. Отправьте боту `/events` — увидите настоящие имена событий.
2. Переопределите нужную переменную (`EVENTS_*`) в окружении Render.
3. Для топа гарментов и источников пейволла имена свойств задаются через
   `GARMENT_PROPS` и `PAYWALL_SOURCE_PROPS` (посмотреть свойства события:
   `/props <имя события>`).

## Локальный запуск

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить
export $(grep -v '^#' .env | xargs)
python main.py            # воркер
python main.py --once today   # разовый отчёт за сегодня
```
